How it works

  1. 1

    You write utility classes

    Utility names and variants such as md:grid-cols-2 and hover:bg-surface.

  2. 2

    Readers set their needs

    The widget changes CSS variables and data-ax-* attributes on <html>. Settings left on automatic follow the operating system.

  3. 3

    Pages ship atomic

    The build compiles each class to a one-declaration ax_ class in one shared stylesheet. A browser test proves the cascade is unchanged.

Variable utilities — your grid's pattern, everywhere

One class per property reads a chain of variables, one per breakpoint, each falling back to the one below — how grid.css picks its columns. Any value, any breakpoint, and a -large value for readers who choose large text. Below: 1 column on phones, 2 from 768px, 4 from 1268px, and back to 1 at 150%+ text.

Atomic engine — one declaration per class

This card is styled with create(), Facebook/StyleX style. Every property becomes one generated class holding one declaration. Hover it, or change text size or contrast in the widget: the classes stay the same, the variables they read change.

const s = create({
  card: {
    padding: vars.space[6],
    borderRadius: vars.radius.lg,
    backgroundColor: {default: vars.color.surface,
                      ':hover': vars.color['surface-2']},
    flexDirection: {default: 'row', '@large-text': 'column'},
    gap: vars.space[4],
  },
});
card.className = classes(s.card);
